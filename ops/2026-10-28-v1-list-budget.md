# API 列表分页读取预算

## 问题与改动

API v1 请求少量文章时，先为候选池中的所有文章读取翻译、中文正文预览、反应和统计，再截取一页。这些同步数据库操作会阻塞同一进程的正文请求。线上修改前请求 `limit=5` 耗时 8.922 秒。

现在先执行原有筛选、排序、since 和 cursor 分页，再只为最终一页组装完整资产和统计。响应字段与正文内容保持兼容。原有搜索范围未扩展。

## 验证

- 新增实际 HTTP 回归：90 篇文章中请求 5 篇，断言不读取页外文章资产；旧实现失败，修复后通过。
- 覆盖连续分页、since、全文搜索、已删除文章、未订阅频道隔离，以及本页中文可用状态和阅读统计。
- 181 项项目测试、8 项可靠性测试、3 项 Python 检查通过；生产依赖审计 0 漏洞。
- 线上延迟与浏览器验收在部署后独立记录，不以本地通过替代。
