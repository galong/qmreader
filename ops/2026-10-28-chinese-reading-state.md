# 中文内容加载状态修复

更新时间：2026-10-28。目标：打开文章时不能把正在读取的中文内容显示为“没有中文”；后台完成后自动显示，并保留用户选择的原文视图。

## 现场与根因

- 用户截图文章 `116952780f0e371471230e0e4307f6ed` 的公共改写已有 9876 字符，最后更新于 `2026-10-27T15:55:06.628Z`；现场 GET 返回正文，列表标记 ready。此次闪烁不是点击后才生成。
- 前端开始 GET 时调用空正文渲染，空文案固定为“还没有中文改写”；失败也走同一分支。较早请求仅按文章 ID 校验，A → B → A 时可能干扰新请求。
- 后台自动改写原已存在；本次保留其源配置和处理范围，不扩大 AI 生成量，不在 GET 中排队或调用模型。

## 修改

- 中文改写和直译分开呈现读取中、处理中、尚未就绪和失败；改写读取中使用转圈和正文占位。
- 后台状态支持有限轮询、完成自动展示、错误重试；不抢走用户选择的原文标签。离开文章、页面隐藏或等待超过 90 秒后停止轮询。
- GET 状态字段兼容旧响应，仅近期有效任务可声称正在处理；过期任务不显示无限处理。精简列表保留准备状态，API v1 携带 `readingState.rewrite`。
- 所有中文读取及手动生成结果按请求序号和文章 ID 校验，丢弃迟到响应。

## 验证与发布入口

- 修改前五个界面回归用例均失败，修改后通过。新增 API 状态、真实匿名 HTTP、A → B → A、重试恢复、有界轮询和手动切换视图回归。
- 隔离浏览器夹具验证 2.5 秒慢响应显示加载状态、排队后自动显示中文、503 显示重试，未调用 AI。夹具不是生产生成任务验收。
- 发布沿用 `scripts/deploy-release.py`：GitHub main 精确提交打包、备份生产代码、保留数据配置、同步独立公共读取中间件、核对运行版本及所有发布文件摘要。生产部署结果以发布回执和 v1.0.9 Release 为准。

## 边界

- 不承诺所有历史文章都已预生成；无可靠任务证据时返回 `not_ready`，不伪装成正在生成。
- 本次验证内容已缓存及模拟排队到正文的状态转换，没有为验收消耗线上 AI 额度。
