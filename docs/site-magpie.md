# Site AI routing through Magpie

Set `SITE_MAGPIE_API_KEY` in the server's private `.env` to enable the site gateway.
A caller supplying their own API key keeps their own provider configuration.
Requests using the site key ignore client model/provider/endpoint headers.

`SITE_MAGPIE_ARGON_UNTIL` is an absolute ISO timestamp. Before this time, new
operations use `aigocode/gemini-4-argon`; at or after it (or when unset), they use
`group/qmreader-deepseek-flash`. This is evaluated by the server on each config
read, survives restarts and requires no desktop scheduler. Already running
operations may finish on their original model. Invalid deadlines fail closed.

The dedicated Magpie key must allow only these two model IDs. The Flash group
has explicit members, no patterns, nested groups, official DeepSeek or Pro:

- siliconflow/deepseek-ai/DeepSeek-V4.1-Flash
- aigocode-team-ds/deepseek-v4.1-flash
- workbuddy/deepseek-v4.1-flash
- workbuddy-ai/deepseek-v4.1-flash
- trae-cn/deepseek-v4.1-flash

Keep this group operator-owned so catalog discovery cannot add new routes.
Flash requests disable thinking. All site calls retain persistent daily,
per-user, concurrency and input/output limits. The existing ledger uses
internal safety allowance units, **not Magpie pricing or an invoice**;
successful calls settle using actual reported token counts.

No existing reading assets are regenerated by enabling this configuration.
To end the trial early, remove the deadline and restart the web service.
To disable Magpie routing, remove the site key and restart (the legacy server
configuration then applies). Back up `.env` and the changed modules before
rollout; never commit credentials.
